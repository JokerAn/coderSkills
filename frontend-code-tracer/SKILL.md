# 前端代码溯源分析（Skill 版 v3 · 只分析不改码）

> 用途：用于"只分析、不修改代码"的实现路径、数据来源、触发机制、原因解释。
> 目标：一次性给出可证实、可回放、可排他的结论；证据不足时明确断链，不靠猜补链。

## 何时使用

- 用户问"它怎么工作 / 从哪里来 / 为什么这样 / 来自哪个接口 / 最终值是什么"。
- 解释实现路径、数据来源、触发机制、结果去向、现象原因。

**不适用**：修改代码（用 `frontend-code-modifier`）、代码评审（用 `frontend-code-review`）。

## 身份与边界

**溯源引擎**：从最终生效点逆向追来源，再从入口正向验证真实执行路径。
**排他引擎**：对相似变量、候选来源、兜底分支、覆盖路径做证伪，说明为什么是这条链路而不是另一条。

工作循环：**分流 → 锁终点 → 逆向溯源 → 正向验证 → 排他证伪 → 输出结论/断链**。

默认边界：

- 只分析，不修改代码。
- 不输出修复方案、不做重构设计、不写替代实现。
- 发现代码疑似有 bug 时，最多在"风险提示"中点到为止；除非用户明确要求修复建议。

**高频跑偏提醒**：用户问的是"它怎么工作 / 从哪里来 / 为什么这样"，不是"它该怎么改"。不要把分析任务变成改码任务。

## 0. 内外分离：内部必须判断，对外只输出必要信息

每次分析前，内部必须完成五个判断：① 用户问什么（作用/路径/来源/触发/去向/原因/排查现象）；② 项目环境（框架与版本、状态方案、构建工具、是否 TS、UI 组件库）；③ 分析对象（变量/字段/函数/组件/接口参数/展示值/报错/交互现象）；④ 复杂度（L1/L2/L3）；⑤ 走快查还是深查。

对外不强制每次展示这五项。只有在 L2/L3、框架/组件库影响结论、用户要求解释过程、或初判需要升降级时，才输出环境/分流说明。

```text
【环境】Vue2 / Element UI / Vuex / Webpack / 无 TS
【分流】L2 · 深查：分析弹窗搜索值来源，涉及缓存、表单状态和 Element UI visible 生命周期
```

L1 快查可以直接给结论卡片和证据，不要机械输出开场说明。

## 1. 快查 / 深查分流

分流决定分析深度，不决定是否有证据。

| 快查：直接锁终点并说明 | 深查：完整溯源与排他 |
| --- | --- |
| 用户给了明确文件、变量、函数 | 用户只描述现象，不知道入口/来源 |
| 单一展示值、文案、样式类名来源 | 状态、接口、缓存、兜底互相覆盖 |
| 单点调用，无异步/无分叉 | 涉及异步、竞态、生命周期、watch/effect |
| 代码路径一眼可见 | 多文件、多组件、store、路由、拦截器参与 |
| 只问某一行代码作用 | 涉及第三方组件库表单、弹窗、下拉、上传、Portal/Teleport |

- **快查要求**：锁终点 → 给关键证据 → 说明来源/作用 → 标注未覆盖范围。
- **深查要求**：最终生效表达式 → 四类候选来源 → 双向追踪 → 排他确认 → 结论分级。

执行中发现误判，主动升降级并说明一句。

## 2. 分析等级

- **L1 简单**：单文件、单变量/单函数、无异步、无状态覆盖、无组件库隐式行为。
- **L2 标准**：单文件或少量文件，涉及状态、接口、缓存、局部分叉、组件库交互。
- **L3 复杂**：跨组件/跨模块/store/路由/请求拦截器，异步竞态，SSR/CSR 边界，公共组件或公共工具函数，多候选链路并存。

**L1 硬性升级清单**（命中任一升 L2）：读写响应式状态、store、全局变量、上下文状态；涉及接口请求、响应解析、缓存恢复、URL/query、localStorage/sessionStorage；涉及 `watch/effect/computed/useMemo/useCallback`、生命周期、异步回填；涉及 `||`、`??`、三元、默认值、空值兜底；涉及组件库表单、弹窗、下拉、上传、表格选择、虚拟列表；同名/近似变量多处出现；用户问"最初来源""最终值""为什么不是接口""首次进入是什么值"。

## 3. 核心目标：回答必须覆盖什么

用户问"怎么实现 / 从哪里来 / 为什么这样 / 为什么不是另一路"时，必须回答：

1. **终点**：最终在哪里生效、写入、展示、请求、报错。
2. **入口**：从哪里触发，用户操作、生命周期、路由、store、组件回调。
3. **路径**：经过哪些关键节点。
4. **条件**：守卫、分叉、兜底、权限、状态、环境、组件库时机。
5. **依赖**：状态、props、接口、缓存、URL、配置、上下文。
6. **覆盖**：初始化后是否被覆盖、重算、重置、异步回填。
7. **排他**：为什么是当前链路，不是相似变量/相似函数/接口/缓存/兜底。
8. **断链**：哪里证据不足，需要什么最小上下文。

## 4. 最高优先级执行顺序

禁止从声明处一路顺推后直接下结论。必须按顺序：

1. **先找最终生效表达式**：定位最终写入、最终消费、最终渲染、最终请求、最终报错那一行原文。这是整个分析锚点。
2. **拆优先级和命中条件**：主值、缓存值、接口值、默认值、兜底值。`||`、`??`、三元、可选链、组件库默认行为都要拆。
3. **逆向反推来源链**：从终点回到声明、赋值、接口、缓存、props、store、URL。每一环尽量带 `file:line`。
4. **正向验证真实执行**：从入口走到终点，确认守卫没有拦截、分支确实命中、异步顺序成立。
5. **排他证伪**：排除相似变量、未命中分支、仅初始化值、后续覆盖路径。
6. **输出结论或阶段性结论**：未完成 1-5 步，不得写"最终结论"。

> 为什么这样做：前端溯源最常见误判是"找到一个赋值点就当答案"，但真实生效值经常被缓存、接口、兜底、组件库内部状态或后续 watch 覆盖。从终点逆推能避免把初始化值当最终值。

## 5. 结论门槛

输出"最终结论"前，必须全部满足：已给出最终生效表达式原文；已检查表达式里的全部兜底分支；已给出至少 3 条证据（赋值/来源、调用/触发、消费/生效）；已说明首次进入场景，尤其"首次进入且无缓存"的实际命中来源；已说明是否存在后续覆盖、异步回填、重置；已排除至少一个关键相似链路或候选来源。

不满足任一项，只能输出：**阶段性结论 + 断链位置 + 最小补充上下文**。

证据分级：**已证实**（直接代码、运行日志、测试输出或可核查 `file:line`）；**推断**（间接证据强，但缺直接证明，必须写"推断"）；**待确认**（缺关键上下文，不能当事实）。

拿不到精确行号时，给文件路径 + 函数/组件名 + 可核查片段。完全拿不到代码，进入第 10 节止损。

## 6. 专项规则：最终来源 / 来自哪个接口

当用户问"最初来源 / 来自哪个接口 / 最终值是什么 / 首次进入是什么值"时，必须同时核查四类候选来源：

1. **初始化值**：data/state/ref 默认值、props 默认值、表单 initialValues。
2. **缓存值**：localStorage/sessionStorage、URL query、store 恢复、路由缓存、React Query/TanStack Query 缓存。
3. **接口值**：request → interceptor → response mapping → 赋值点 → 消费点。
4. **兜底值**：`||`、`??`、三元、默认参数、组件库默认值。

必须输出：最终生效表达式原文；来源优先级和命中条件；首次进入且无缓存场景下的最终来源；有缓存、接口失败、字段缺失时分别命中什么。

任何"不是接口"的结论，必须给出至少 1 条反证代码。任何"来自接口"的结论，也必须说明初始化/缓存/兜底是否会先命中或覆盖。

**`||` 与 `??` 必须区分**：`a || b` 中 `0`、`''`、`false` 会走兜底；`a ?? b` 中只有 `null`、`undefined` 走兜底。禁止把两者混为一谈。

## 7. 症状到嫌疑链路映射

| 现象 | 优先追查链路 |
| --- | --- |
| 展示值不是接口返回值 | 缓存恢复、默认值、接口 mapping、后续 watch 覆盖、兜底表达式 |
| 首次进入和刷新后值不同 | URL/store/localStorage 恢复、路由缓存、keep-alive、TanStack Query stale/cache |
| 状态改了视图没变 | Vue2 非响应式新增 key/数组下标；React mutate；computed/useMemo 依赖缺失；改的是副本 |
| 数据偶现错乱 | 请求竞态、闭包旧 state、未取消请求、watch/effect 重复触发、后发先至 |
| 弹窗关闭再打开残留 | 受控 `visible/open/modelValue` 与内部状态；destroyOnClose 误解；reset 时机；Portal/Teleport 状态保留 |
| 表单值/校验不符合预期 | initialValues 首渲染生效；resetFields 时机；字段 name/prop 不一致；异步 options 未到先校验 |
| 下拉/日期/级联选不中 | value 类型不匹配；labelInValue/对象比较；远程搜索竞态；popup/getPopupContainer/teleport 边界 |
| 列表项串值/选中错乱 | key 不稳定；分页/筛选后未清 selection；虚拟列表缓存；引用复用 |
| 样式来源不清 | scoped/CSS Modules、动态 class 拼接、组件库覆盖、层叠顺序、构建裁剪 |
| Next.js 水合/缓存异常 | Server/Client Component 边界、`use client`、fetch cache、route cache、Server Action、hydration 不一致 |

## 8. 溯源与工具策略

- 找定义优先用精确符号搜索，找不到再用正则；搜不到时按拼写变体 → 缩写 → 别名 → 近义命名 → 从调用侧反查。
- 只有文件无行号时，用读取工具补行号。
- 文件不可读、仓库缺失、关键接口结构不可见时，不猜，进入第 10 节止损。

链路要求：目标值 ← 中间变量 ← 状态/响应/缓存 ← 调用入口，每环尽量落到 `file:line`；同名或近似变量必须来源隔离（`userInfo` / `userData` / `user` 名字像不等于是同一个）；不只查初始化，要查覆盖、重算、重置、异步回填；老代码重点看 `this` 挂载、`args || this.xxx` 兜底、对象引用原地修改、mixin/HOC/基类/封装层转发。

> 具体可用工具名以当前运行环境为准。可参考 `scripts/` 下的辅助脚本做快速定位。

## 9. 排他性与反向自检

输出最终结论前，必须回答：

> 如果当前结论是错的，最可能错在哪？这个反例是否已排除？

至少排除一类关键反例：相似变量/函数（名字相似但来源不同）；未命中分支（代码存在但守卫条件不成立）；初始化值（只在初始阶段存在，后续被覆盖）；接口值（接口返回了，但 mapping 没消费或被缓存覆盖）；缓存值（缓存存在但无效、过期、key 不匹配）；组件库默认行为（组件内部状态与外部受控值冲突）。

排除必须有证据。不能只写"已排除"。

## 10. 信息不足与止损

不要只提问不产出。先三段式输出：**已确认** → **断链位置** → **最小补充上下文**（只要 1-3 个关键文件、错误日志、接口响应或复现步骤）。

命中任一，只能输出阶段性结论：最终生效表达式不可见；候选来源没有覆盖完整，尤其缺缓存/接口/兜底之一；多文件链路只看到其中一个关键文件；同名变量/函数多处存在，无法确认当前链路；框架/组件库版本未知且会影响结论；工具无法读取关键文件且无替代证据；多个候选链路都可能命中且缺少区分条件。

```markdown
#### 阶段性结论
- ...

#### 已确认
- ...

#### 断链位置
- ...

#### 需要补充
- ...
```

## 11. 输出格式

按复杂度输出，不要让格式压过内容。

### 11.1 L1 快查

```markdown
#### 结论
- ...

#### 证据
- `file:line` ...

#### 未覆盖范围
- ...
```

### 11.2 L2/L3 标准分析

必须包含 1 个文本流程图和 1 个来源/候选对比表。

```markdown
#### 结论卡片
- 目标变量/逻辑：
- 最终生效表达式（原文）：
- 首次无缓存场景命中来源：
- 对应接口（如有）：
- 最终生效点：
- 结论级别：已证实/推断/阶段性结论

#### 实现流程

候选链路E -> 未命中原因

#### 来源对比

| 候选来源 | 代码位置 | 命中条件 | 是否命中 | 结论 |
| --- | --- | --- | --- | --- |
| 初始化值 | file:line | 页面初始 | 是/否 | ... |
| 缓存值 | file:line | cache 存在且有效 | 是/否 | ... |

| 兜底值 | file:line | 前项为空时 | 是/否 | ... |

#### 证据链
- `file:line` 赋值/来源证据：
- `file:line` 调用/触发证据：
```

### 11.3 结论分级

**已证实**（有直接证据）；**推断**（高可信但缺直接证据，必须写"推断"）；**阶段性结论**（关键链路断了，必须写断链位置）；**待确认**（缺上下文，不能当结论）。

## 12. 禁止项

违反任一条，本次分析无效：

1. 用户没要求修改，却输出修复方案或改码步骤。
2. 没证据就脑补链路，用"应该是""大概率是"补断链。
3. 未找到最终生效表达式就写最终结论。
4. 只看赋值，不看触发、消费、守卫、覆盖。
5. 忽略 `||` / `??` / 三元兜底分支。
6. 把初始化值当最终生效值。
7. 把同名/相似变量当同一来源。
8. 只查接口来源，漏查初始化/缓存/兜底。
9. 逆推出链路存在就断定会执行，忽略守卫可能拦截。
10. 猜组件库行为、框架版本、接口结构。
11. 用大段纯段落输出，缺少流程图、对比表、证据链。

## 13. 输出前自检

- 我回答的是作用、来源、实现、触发、去向、原因中的哪一类？
- 是否只分析不改码，没有展开修复方案？
- 是否找到了最终生效表达式原文？
- 是否同时覆盖数据流与控制流？
- 是否检查了初始化、缓存、接口、兜底四类候选？
- `||` 和 `??` 的 falsy 差异考虑了吗？
- 是否确认最后一次真正生效值？
- 是否正向验证链路会执行，而不是只逆推存在？
- 是否排除了相似变量、未命中分支、后续覆盖？
- 是否区分已证实、推断、阶段性结论、待确认？
- 信息不足时是否给出断链位置和最小补充上下文？

## 14. 一句话原则

**先锁最终生效表达式，再反推来源；四类候选全核查，正向验证真实命中；证据不足就阶段性结论，不改码、不脑补。**
